Decision (her, 30 Sep; threshold revised 1 Oct): only skills the student has count (A8 same skill or
SBERT >= 0.7). First set at 0.8, then checked on the Nokia Network Engineer Graduate Program job (12 skills,
about 7 really held): 0.6 counted 9 (2 wrong: Network automation <- Test automation, Performance monitoring
<- Performance testing), 0.8 counted 2 (missed 5, e.g. Team collaboration <- Teamwork 0.76, Cloud computing
<- cloud security 0.70), 0.7 counts 6 (1 wrong, misses Troubleshooting 0.66 and Data analytics 0.61).
The labelled sample agrees: 0.70-0.80 band 15 of 16 at least mostly right, below 0.7 about 40% wrong.
Skill Gap is strict and plain: have / to learn, with no "related" or "partly covered" reasons and no CV
extras, because closeness below the line is not reliable evidence and weak explanations mislead users
(Papenmeier et al. 2019). A partial credit (0.25-0.5) was rejected: any value is a judgement that can't be
measured without manual labels. Related knowledge still lifts a job in the Best-fit order through the
whole-profile SBERT similarity. Known remaining errors: the look-alike and missed examples above.
Planned fix (to agree with the supervisor): a trained skill relationship classifier (fix plan, Stage 2).
