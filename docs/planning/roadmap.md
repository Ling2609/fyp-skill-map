## Positioning (decided 27 Sep)
**SkillMap is a university career platform.**
- **The university supplies the official academic record** (modules + grades). In the FYP this is *simulated* with seeded demo data or a CSV import done by Admin. Real integration with the university's student-records system is **future work**, and the report says so.
- **Module skills (decided 28 Sep, "option 2"):** the admin supplies the **module descriptor** (code, name, description / learning outcomes); **SkillMap extracts the skills from the descriptor text** (IR Objective 1); the **admin reviews** them (remove / fix) before students see them. Not "admin types the skills": that would remove Objective 1 and universities don't keep industry skill lists per module. In the FYP the catalogue is `data/modules.json`, based on the APU BSc SE programme brochure (2026) per `data/README.md`; the extracted skills must follow from those descriptors. Optional upgrade: fuller APU module descriptors / learning outcomes for a few modules
- **Students can optionally add their own evidence** (projects, certifications). This is labelled **self-declared**.
- **Employers are the university's industry partners.** They post jobs and see matched students who have opted in.
- **Admin is the career office.** It imports the module catalogue and student academic records.
- **Students never have to "prove" anything.** Matched skills (Direct or Related) count as skills the student has, with no action needed. Only gaps (Partly covered / Missing) get "Learn →".

**Job data (decided 27 Sep):**
- **Job Matches shows live jobs only** (JSearch API, current MY + SG ICT openings with real "Apply on LinkedIn/JobStreet/company site ↗" links). There's no point recommending a job the student can't apply to.
- **The 2024 JobStreet dataset** is **data, not recommendations**. It powers Career Paths (C4), market statistics (C1–C2), "learn first" priority (C3), the simulator's role alignment (D), and possibly SBERT fine-tuning (see B5)
- **Dataset size (checked 27 Sep):** the Kaggle file has 69,024 MY postings → `clean_jobstreet.py` keeps ~8,000 ICT jobs → `extract_job_skills.py` targets a **6,000-job stratified sample** (`SAMPLE_SIZE = 6000`), but the run stopped at the Groq limit: **2,446 in the DB, ~2,340 with skills**. Enough for Phase C (the sample is spread across subcategories and shuffled). Optional top-up: see C0. Report it as "2,446 of a 6,000-job stratified sample" (or the final number)
- **Market statistics use Malaysia only** (`country = 'MY'`)
- **Live pool target: about 200 jobs** by the demo (133 on 29 Sep after duplicate and non-ICT clean-up)

**Scores (decided 27 Sep, Dashboard updated 28 Sep):**
